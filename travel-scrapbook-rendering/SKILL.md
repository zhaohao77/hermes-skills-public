# 旅行手账图渲染（HTML → 9:16 PNG）

把一份**已经确定的行程**渲染成一页或多页 **1080×1920（9:16）** 的手账图，
**旅途中在手机上翻着走**。定位：`travel-guide` 出 Word/Excel 做**出发前的功课和存档**，
本技能出**旅途中用的图**——两者互补，不是替代。

## ⚠️ 第一原则：**不要用 AI 文生图模型画这种图**（某日 实测踩死）

用 `Kwai-Kolors/Kolors`（SiliconFlow）直接生成"9:16 中文旅行手账页"，实测**彻底失败**：

| 技能要求 | 文生图实测 |
|---|---|
| 清晰可读的中文标签 | ❌ 全是乱码伪汉字 |
| 虚线路线 + 编号节点 | ❌ 完全没有 |
| Day 徽章 / 时间卡 / 门票卡 / 提醒气泡 | ❌ 一个都没有 |
| 路线优先的行程板 | ❌ 退化成"古建筑贴纸大杂烩" |
| 白边贴纸 / 9:16 | ✅ 仅这两项达标 |

**根因**：文生图模型**只会画"风格"，不会装"信息"**；中文渲染能力≈0，信息密度一高就崩。
换模型（即梦/可灵/Qwen-Image）只能让乱码好看一点，**文字依然会错**。

→ **正解：HTML/CSS 渲染 → Edge CDP 截图。** 文字是真字体渲染，**100% 准确**。

> ⚠️ **某日 用户否决：头图（景点头图）也必须用实景照片，不能是 AI 插画。**
> 原话：「**动物园不去了没什么特色，头图用郑州代表性照片吧**」。
> 当时 D6 的 hero 是 Kolors 生成的动物园插画（`gen_d6_hero.py`，脚本自己都注明"非实景照片，交付时必须如实说明"），
> **风格与 D1–D5 的实景照片不一致**，用户一句就换掉了。
> → 文生图只剩「**风格底图 / 装饰性插画**」这一小块用途；
> **凡是代表"今天去哪"的 hero 图 = 实景照片**。实景照的来源与许可写法见下节「取景点图」。
> → 万一手上有 AI 图又必须用，**图上要加角标**「示意图（AI 插画 · 非实景照片）」——但默认别走这条。

## 🎨 配图策略（用户明确要求 · 铁律）

**只给「景点」配 1 张代表性图片，其他位置一律不配图。**

用户原话：「**景点里配一张有代表性的图片就行，给孩子们提前视觉效果，其他就不用配图**」

**为什么**：
- 配图的目的是**给孩子一个"今天要去哪"的视觉预期**，不是装饰
- 车站 / 换乘 / 地铁 / 酒店这些**流程性节点配图没有认知价值**——孩子不会因为看到车站照片而兴奋
- 图越散页面越杂，反而**削弱行程信息的可读性**

> 🔴 **踩过的坑**：第一版给 D1（出发日）配了 5 张站台/列车图、给 D2 配了 6 张散在各节点，
> **用户当场全部否掉**。改法是"D1 归零、D2 只留顶部 1 张通栏横幅"，一次通过。

| 天 | 配图 |
|---|---|
| **出发日 / 返程日，且那天没有景点** | **完全不配图**，纯卡片 |
| **返程日但上午排了景点**（某日 D6 实例） | **照配 1 张** —— 返程日上午去二七广场，hero 就用**二七纪念塔实景照**。⚠️ 别因为"是返程日"就机械删图 |
| **有景点的日子** | **只配 1 张**，放**页面顶部**（标题下方）做通栏横幅，高度 ~240px、占满整宽 |

- 横幅标签写「**今天去这里 ｜ 景点名**」，直接点明用途
- **选图原则**：选**最有辨识度**的那张（只有河南→夯土大墙+园名横幅；龙门石窟→卢舍那大佛；万岁山→打铁花），
  **不要**选"园区俯瞰平面图"这类信息向但没情绪的照片

## 🛠 制作流程

1. **备数据**：从行程 JSON / 攻略里取当天的路线节点、硬时间点、门票、餐饮、住宿、提醒。
   **事实不得改写**（车次号、时间、票价、酒店名、电话一律原文照抄）。
2. **定页数**：不要机械"一天一页"。跨城日、有硬卡点日、有景点日各自独立；同城轻装日可合并。
3. **写 HTML**：复制 `templates/scrapbook-page.html` 改内容（样式骨架别重写）。
4. **渲染**：跑 `scripts/render_scrapbook.py`（改顶部 `JOBS` 列表即可批量出图）。
5. **自检**：截图后**看一眼图**再交付——查三件事：中文有没有乱码、有没有溢出/截断、底部有没有大留白。

### 溢出压缩（DOM > 1920）照这个顺序动，别删信息

| 旋钮 | 本次幅度 | 省下 |
|:--|:--|:--|
| `.hero-img` 高度 | 230 → 180px | ~45px |
| `.node` margin-bottom | 9 → 5px | ~24px（6 个节点） |
| `.card` padding 上下 | 10 → 8px | ~24px |
| `.val` font-size / line-height | 27 → 25px / 1.30 → 1.26 | ~20px |
| `.sub` font-size | 22 → 20px | ~12px |
| `body` padding | 22/18 → 20/16px | ~8px |
| intro / booklink / foodbar padding | 各 −2px | ~10px |
| 同义句收紧 | 长句去掉修饰（不删事实） | ~30px |

**2047 → 1920 一次到位。目标不是"塞得进"，是正好卡住上限**（渲染脚本会打印 `DOM 1080x1920 ... OK`）。
⚠️ **绝不靠删节点/删字段来换高度**——信息完整优先，只压排版和措辞。

### 🖼 通栏横幅的 `object-position` 坑（本次实踩）

hero 通栏是 **≈5.7:1 的极扁条**，而器物照/人像照多是 4:3 或竖构图 → `object-fit:cover` 会上下狂裁。
本次莲鹤方壶照用默认 `object-position:center 40%`，**把鹤的头颈整个切掉**（只剩翅膀和壶身）；
改成 `center 16%` 后主体完整。

→ **规则**：换 hero 图后用 `vision_analyze` 专门看一次裁切，问"**主体头部/顶部在不在画面里**"。
主体偏上的用 `center 10%~20%`；只有主体居中时才用 `center 40%`。
**别再套用上一张图的 object-position。**

## 🕳 已踩的坑（照单避开）

| 坑 | 现象 | 解法 |
|---|---|---|
| **Playwright 自带浏览器缺失** | `p.chromium.launch()` 报 `Executable doesn't exist ... chrome-headless-shell.exe` | ✅ **首选：`launch(headless=True, channel="msedge")` 直接起本机 Edge 内核**——某日 实测可用，**不用开 Edge、不用 CDP 端口、不用探活**。写法：`for kw in ({"channel":"msedge"},{"channel":"chrome"},{}):` 逐个 try 兜底（见 `scripts/render_scrapbook.py`）。CDP 路线（`connect_over_cdp("http://127.0.0.1:9223")`）降级为兜底 |
| **Edge CDP 掉线** | `connect ECONNREFUSED 127.0.0.1:9223`（用户关了窗口） | 截图前先探活 `Invoke-WebRequest .../json/version`，掉线就重启 Edge（带 `--remote-debugging-port=9223 --user-data-dir=$HOME\EdgeProfile`） |
| **DOM 高度 > 1920** | 截图底部被截断 | 压缩间距（`margin-bottom`、`padding`、槽位高度各减几 px）——**不要用 `zoom` 缩放**，Playwright 下不稳 |
| **删图后残留内层块** | 用正则删 `<div class="inline-slots">…</div>` 只删了外框，内层 `.islot` 留着（页面仍显示图） | 用**按 `<div>`/`</div>` 配对计数**的函数删（见 `scripts/render_scrapbook.py` 里的 `strip_class_blocks`），删完 `count('<img')` 复核 |
| **删图后底部大留白** | 内容变短，下方空 400px | 给 `body` 加 `display:flex; flex-direction:column; justify-content:space-between`，让各块自动分散填满 |
| **标题换行** | 长标题被挤成两行（如"出发/日"） | 缩短 h1 文案，把"出发日"这类词挪到副标题行 |
| **PowerShell 5.1 中文乱码** | 含中文的 `.ps1` 被按 GBK 读 | 用 Python 脚本改 HTML/JSON，或把命令内联进 terminal |
| **探位视口 ≠ 截图视口** | 先用视口高 **900** 探出各区块 `top/h`，再用视口高 **1200** 截图 → 裁到的是一片空白（封面是 `100vh`，**视口一变所有区块坐标全偏**）。（某日 在 trip-planner 源码包上实测） | **探测与截图必须用同一个 `viewport`**，且把视口高固定写死成常量。截超出视口的区块要 `screenshot(full_page=True, clip={...})`——**只给 `clip` 不带 `full_page=True` 会报 `Clipped area is either empty or outside the resulting image`** |
| **脚本命名遮蔽标准库** | 探位脚本取名 `inspect.py` → `from playwright.sync_api import sync_playwright` 崩 `ImportError: ... partially initialized module ... circular import`（`asyncio` 内部要 `import inspect`，被同目录同名文件顶掉） | **别用 `inspect.py` / `json.py` / `types.py` / `random.py` 这类标准库同名文件当脚本名**（改成 `probe_layout.py` 即可）。报错长得像 Playwright 坏了，实则是命名问题——**排查前先看自己的文件名** |

## 🖼 取景点图（Bing 图片搜索 → 原图 URL）

**不要**用携程/景区的图（常有反爬或登录墙）。走 Bing 图片搜索更快：

1. `browser_navigate` → `https://cn.bing.com/images/search?q=<URL编码的关键词>`
2. `browser_console` 取原图（**缩略图 URL 不要用**，真图藏在 `a.iusc` 的 `m` 属性里）：
   ```js
   JSON.stringify([...document.querySelectorAll('a.iusc')].map(a => {
     try { const m = JSON.parse(a.getAttribute('m')); return {u: m.murl, t: m.t}; } catch(e){ return null; }
   }).filter(Boolean).slice(0, 25))
   ```
3. **过滤掉付费图库站**（这些出来带水印或要付费）：
   `nipic|vjshi|699pic|dashangu|3158|zcool|58pic|zhitu|huitu|qiantu|ibaotu|tuchong|veer|sheitu|5188`
   → 优先留**新闻/百科/官方**源（新浪 `sinaimg`、知乎 `zhimg`、大河网 `dahe.cn`、百度百科 `bkimg`、`gov.cn`）
4. 下载后**生成缩略图拼图**（PIL 5 列网格）用 `vision_analyze` **一次看完挑图**——比逐张看快得多
5. **版权**：新闻报道类公开图，**个人旅行手账自用可以**，**别公开发布或商用**——交付时要跟用户交代清楚
6. **⭐ 更优先的路线：Wikimedia Commons**（许可明确可溯，图上能直接标 `CC BY-SA 4.0`）。
   Bing 抓来的新闻图**许可不明、标不出来**；Commons 每张都带 `LicenseShortName` + 作者 → **来源可溯**
   （用户要"数据/来源可核验"，配图同理）。中文关键词也能搜到。

   ```python
   # ① 先搜文件名（srnamespace=6 才是文件；中文如「二七纪念塔」有效）
   api({'action':'query','list':'search','srsearch':'二七纪念塔','srnamespace':'6','srlimit':'8','format':'json'})
   # ② 再用文件名批量取 URL / 尺寸 / 许可
   api({'action':'query','titles':'File:A.jpg|File:B.jpg','prop':'imageinfo',
        'iiprop':'url|size|extmetadata','format':'json'})
   ```
   ⚠️ **别用 `generator=search` + `prop=imageinfo` 想一步拿完** —— 某日 实测**返回空**，白跑一轮。
   ⚠️ 只收**横版且宽 ≥1200**（hero 是极扁条，竖版裁出来没法看）。

### 🖼 细高地标：hero 必须**按最终尺寸试裁**再定 `object-position`（某日 补）

hero 通栏是 **≈6:1 的极扁条（1080×180）**。**细高型地标（塔 / 尖顶 / 高炉）横条必然只能取一段** ——
**别套用上一张图的 `object-position`**，先按 **1080×180 的真实尺寸**试裁几个位置再定。

本轮实测（二七纪念塔 · 细高双联塔）：默认 `center 47%` **只剩塔身中段**，改成 **`62% 20%`** 才把
**双联塔尖对称地框在中央** —— 那才是这座塔的招牌特征。

做法（一次看完全部候选）：用 PIL 把候选图各按 `1080×180` 裁 3–4 个位置、**拼成一张联络图**，
**一次 `vision_analyze` 既挑图又定 `object-position`**（比逐张试渲快得多）。
