# 旅行交付物设计规范

管的是**同一份行程，怎么变成给家人（尤其带孩子的家庭）真正好用的交付物**。
数据怎么查、行程怎么排 → 属于 `life/travel-guide`、`life/travel-scrapbook-itinerary`、`life/trip-advisor`。
**本技能管"呈现"**：配什么图、写什么字、信息怎么分工。

## 触发条件

- 用户要把行程做成文档/表格/图片交付给家人
- 用户对已交付的攻略/手账图提出修改（"配图不对""重复了""挡住字了""缺介绍"）
- 主动给带孩子的家庭做行程交付物时（默认按本规范执行，不用等纠正）

## 五条铁律（某日 用户连续 5 次纠正后固化）

> 这些不是一次性建议，是这位用户对旅行交付物的**稳定偏好**。下次直接照做。

### 铁律 1｜只给「景点」配图，其余位置一律纯文字

用户原话：「景点里配一张有代表性的图片就行，**给孩子们提前视觉效果**，其他就不用配图」

| 位置 | 配图？ |
|---|---|
| **要去的景区/园区** | ✅ 配 **1 张**（放页面顶部，横幅式） |
| 车站 / 地铁 / 换乘通道 / 车厢 | ❌ 纯文字卡片 |
| 酒店 / 餐厅 / 美食 | ❌ 纯文字卡片（用户单独要再给） |
| 出发日 / 返程日（**无景点**） | ❌ **整页无图**，用开篇简介卡替代 |

**理由**：配图的目的是"给孩子**提前的视觉预期**"（知道要去什么样的地方），
**不是**"把行程做得好看"。车站照片对这个目的毫无贡献，反而稀释重点。

### 铁律 1 附则｜用户单独要「当地特色美食」→ 走**文字条**，仍然不配图（某日 用户令）

用户原话：「然后**都要更新当地的特色美食推荐**」—— **每页都要有**，但图仍然只给景点（铁律 1 不变）。

**做法**：每页在 `.bubbles` 之前插一条 `.foodbar`（样式：米黄底 `#FFFBF0`、棕边 `#E8CF9C`、棕字 `#6B4E22`、字号 19.5–21px）：
```
🍜 当地必吃｜<3–4 个当地特色> —— <一句吃法/点法提示>
```

**三条纪律**：
1. **每页只写"当地"的**：D1 中牟早点（胡辣汤·油馍头·水煎包；孩子怕辣点「两掺儿」）·
   D2 园内河南老字号（第一楼灌汤包·方中山胡辣汤·洛阳水席·裕丰源烩面）·
   D3 开封夜市三选（西司=本地人最多 / 老河大西门=就在住的河大片区 / 鼓楼=游客多）+ 必吃 ·
   D4 园内老字号 + 坐船顺路的夜市 · D5 洛阳汤食（牛肉汤·不翻汤·浆面条·烫面角）。
2. ⚠️ **餐厅不要占行程节点**（某日 用户当场纠正，**本条早先的写法已被推翻**）：
   旧写法是「分层写：店名放行程节点，地方风味放美食条」→ **已作废**。用户原话：
   「**我是说地锅鸡也变成美食可选项，而不是必要步骤**」。
   - **行程节点只放"要做的动作"**（赶车 / 入园 / 取行李…）；**具体某家餐厅 = 可选项，一律下沉到美食条**。
   - 反例：D1 曾把「淼泰城地锅鸡」单独立成一个节点（「19:45 到店 · 晚饭**去县城吃**本地馆子」）
     —— 等于把一家店升格成必做步骤。改成「🍜 19:45 到店 · **晚饭灵活安排**：就近吃 / 点外卖 /
     去县城 约 7 km」+ 一句「想吃当地特色 → 见下方「中牟必吃」」，店名挪进美食条的
     **「晚饭可选」**组（与小龙虾、烩面平级）。
   - **判断口诀：「不去会漏掉什么吗？」** 会漏（车 / 票 / 入园）→ 节点；只是"更好吃" → 美食条。
   - 顺带：节点里那句含糊的「不想折腾可**站内吃**」也被点名删掉 —— **写不确定的方位词
     （站内 / 那边 / 门口）等于没写**，要么写清（"酒店周边"）、要么删。
   - 美食条首组因此固定叫「**晚饭可选**」这类"可选"口径，别用"推荐"（"推荐"会被读成"必须去"）。
   例：节点写「晚饭 · 淼泰城地锅鸡」，美食条就写「河南早点必点三样…」—— 两者不重名。
3. **信息必须核实**（见 `travel-fact-verification`）。本轮核实到的可复用事实：
   开封三大夜市里 **老河大西门夜市（河南大学明伦校区西门）就在河大亚朵那片**、**18:30 才出摊**、
   营业到次日 1 点，招牌 **焖烤鸡腿饼 / 华侨卷粉**；**西司夜市**在包公湖丁角街，坐船西司码头下船即到。
4. **要"写足"，不要一两样打发**（用户原话：「D1 的美食选择**是不是单调了**，作为外省人，
   **当地特色有名的口碑好的都可以推荐试试**」）—— 只写"早点三样"= 单调。**分 3–4 组、每组一行**：

   ```
   🍜 <城市>必吃｜<招牌菜 3–4 个>（可带老店名，如"卤兔肉 · 20 年老店「吴庄张富贵」"）
   【本地名菜】… ｜ 【风味小吃】…
   【口碑店】<店名>（年数 / 招牌菜）· …
   【早点 / 吃法】<怎么点>（如"胡辣汤＋油馍头＋水煎包；孩子怕辣点「两掺儿」"）
   ```

   - **每个店名/菜名都要有出处**，不许凑。两个高产地：**当地官方发布号的美食攻略**
     （如「中牟发布」的必打卡榜：特色名店 / 名菜 / 风味小吃三张表）+ **"一县一菜"类榜单**
     （中牟＝**铁锅蛋**，清末传下来的代表菜，外地基本吃不到，最值得点）。
   - ⚠️ **一写多就会超框**：扩写后先量**真实内容高**（`body` 临时 `height:auto`，见「本机实现要点」），
     超标时**先微收行距/间距、不要砍刚写好的内容** —— 用户要的就是"写足"。
     实测可用的省法：`.foodbar` 字号 21→19.5px、行高 1.44→1.36、`.node` 间距 10→8px
     （三处共省 30px，D1 由超框 28px 变为余量 29px）。
   - ⚠️⚠️ **每页的基线不同，别照抄别页的数字**（某日 D5 实证）：
     D1 当时是 `21px / 1.44 / node 10px`，但 **D5 那页密度早就被压过了**（`val 25 / sub 20 / node 5px`）
     —— 同样的四刀只能收到「`.foodbar` 20→**19px**、行高 1.4→**1.34**、padding 8→**6**、
     `.bubbles` margin-top 6→**2**」，合计才省 **25px**（1945 → **1920 正好**）。
     → **动手前先 grep 这一页当前的 CSS 值**，再决定从哪一档开始；同一批页面**字号要看起来一致**，
     把已经压过的页再压一轮，会和邻页明显不齐。
   - ⚠️ **压不动时：先改「新增块自身的排布」，别把整页再压一轮**（某日 D3 实证）。
     该页密度此前已被压过（val 25 / sub 20 / node 5px），**再压就与同批页面字号不一致**了。
     正确顺序：**① 改块内排布 → ② 收这一块自己的 padding/字号 → ③ 最后才动全页字号**。
     本次「🎁 门票赠三园」块：4 行（标题行 + 每园一行，行行折行 ≈**131px**）
     → **2 行紧凑信息条**（用 `｜` 把三个园串成一段，**信息一字不丢**，仅 **70px**）→ 省 61px，
     D3 由 1967（超 47px）收口到 **1903（余 17px）**，且没有牺牲任何内容。
     **判据**：\"小标题 ＋ 逐条换行\"的多行结构，在窄栏里几乎必然折行；
     **换成\"标签 + 分隔符串联\"的单段条**，往往一次省半屏，视觉上也更像\"补充信息条\"而非又一堆正文。
   - 改完回读 grep **易错字**：本次手打「这幺」被自查揪出 → 形近字（幺/么、巳/已、拔/拨）
     建议单独跑一遍 grep，图上小字肉眼靠不住。

### 附则二｜可选项（游船 / 演出）要「提升为手账节点」时 —— 归哪天看「地理顺路」（某日 用户令）

用户原话：「**我是要你把游船放在 D4**」——⚠️ 注意这句话的**形态**：
**用户重述一条提过的需求 = 上一轮放错了日期或放错了载体**。
先回头找它现在躺在哪（本轮它在 `itin.json` 的 **D3 tips** 里，**压根没进手账图**），再动手；
**不要凭这句话从零重排行程**。

**判定归哪天的顺序**：
1. **看入口 / 码头位置**：汴河游船的「清园翰园码头」＝**清明上河园正门马路对面** → 归 **D4**（清明上河园那天），出园即到，不用专门跑一趟。
2. **看当天节奏有没有余量**：D3 已是「10:30 进园 → 21:30 出园」的满档日，塞不进；D4 晚饭后正好有一段空档。
3. **两条都满足才算顺路**：只是想玩但地理上不顺路 → **单独列成候选交给用户定**，别硬塞进某天。

**落地三件套（缺一样就等于没改）**：
- **手账图**：新增节点，用 `hero` 深色卡突出"今天新加的"；**价格只写底部费用卡**（铁律 5），
  票务规则（怎么买 / 能不能用联票）写进节点；
- **数据源 `itin.json`**：旧载体里那段**搬走、不要复制**（本轮从 D3 tips 删掉 → 写进 D4 的 evening/tips），
  并**顺手核对价格是否过期** —— 本轮发现底稿写的"万岁山联票 99 元"是旧价，
  官方 **2025-10-01 起已调为 128 元/人**（万岁山门票同期调为 100 元），一并更正；
- **费用卡**：新增一行（如"游船夜游 60 元/人（往返）"）。
- ⚠️ 加完节点**必须重量真实内容高**（见「本机实现要点」的 flex 压缩诊断）——
  本轮 D4 正是加节点之后才暴露出景点图被压成 128px 的。

### 附则三｜带娃行程：园内「代步设施」必须单独核实（某日 实测）

**为什么单列**：这类信息**官方攻略基本不写**（它们只讲"看什么"），但对带孩子们的家庭是刚需 ——
`<园区> 代步车 / 观光车 / 婴儿车 / 轮椅 租借`。**查不到 ≠ 没有**，要写"以现场公示为准"并建议入园问服务台。

**核实结论分三档写**：

| 核实结果 | 怎么写 |
|---|---|
| **查到有** | 写清**怎么租 / 参考价 / 门槛**。本次万岁山：可扫码租「小马嘟嘟」智能代步车（2023 年进驻，武侠款定制车身），**需 C2 及以上驾照**；同类景区行业价 **40–80 元/半小时**、押金 200–500 元 —— 一律标「**以现场公示为准**」，别写死 |
| **查不到** | 明说"**官方攻略与游客实测都没提到**"，再给**理由**。本次只有河南：核心区仅 **328m × 328m**（56 格格子院落 + 21 剧场塞在里面），剧场间步行 3–8 分钟，官方反复强调的只有「**一定要穿舒适的鞋子**」→ 结论=按步行设计，入园问服务台 |
| **别混淆** | ⚠️ **「摆渡车」要看清是哪一段**：本次只有河南的摆渡车是**酒店 ↔ 园区接驳**（只有剧场酒店配套），**不是园内代步**。写错会让用户以为园内有车 |

**自洽性检查**：图上「今日强度」类面板（如 `步行 8–12 km`）要与代步结论**互相印证** ——
**没车的大园区，那条强度提示就是唯一的提醒**，别一边写"步行 8–12km"一边让人以为有车可租。

**新增一条事实后，必须反查同页被它证伪的旧表述**（某日 实证）：
确认"万岁山有代步车"之后，D3 底部胶囊里的「**👟 全程步行** 穿软底鞋」当场变成**假话** —— 必须改。
本次改法：`🛵 500 亩 · 园内有代步车可租` 替换掉"全程步行"那条，并把"穿软底鞋"**合并进另一条已有胶囊**，
**不新增胶囊**（胶囊行数一变就会折行，一次撑高 40px+，余量不够就超框）。
**反查词**（改完 grep 一遍）：`全程步行` / `只能走路` / `没有车` / `步行`。
> 与铁律 14 的「反查词」同源 —— **每新增一条事实，都要回头扫一遍它让哪句旧话失效了。**

**图上不写电话号码**（用户原话：「**电话就不要了**」）：
手账图是**旅途中翻**的，电话属于"行前打电话问"的动作 —— 塞进图上既占位置、那一刻也用不上。
查到电话**留在对话与底稿 `itin.json` 里**，**不上图**（真要用，官方公众号里就有）。
同理：**"该打哪个电话确认"这类动作项**也归 行前清单 / D−1 的「今天要办」，不进途中页。

**只有「确定的信息」才上图**：单条低可信来源（问答站 / 自媒体孤证）**一律不进交付物**。
本次清明上河园"疑似有 12 座观光车"就**只在对话里说明、没写进 D4**；
而万岁山"有代步车"（厂商项目官宣）才上了 D3。
分档判据、官方核实的三处高产地（服务设施条目 / 官方公告落款 / 厂商官宣）见
`travel-fact-verification` **铁律六**。

### 铁律 2｜图要"一眼认出这是哪个园区"——地标感 > 视觉冲击

踩过的坑：万岁山用了「打铁花火星特写」、清明上河园用了「虹桥夜景一角」→ 被当场否掉：
> 「配图都没有突出园区的**整体性和标志性景观**」

| ❌ 错（活动 / 细节） | ✅ 对（地标 / 整体） |
|---|---|
| 打铁花、灯光秀局部、民俗表演 | **园区大门 / 牌坊**（画面带园名最佳） |
| 单个建筑特写 | **全园俯瞰 / 航拍全景** |
| "最震撼的那张" | **"一眼能认出这是哪儿"的那张** |

**选图口诀**：先找「**大门 + 园名**」，再退而求「**鸟瞰全景**」。
**搜索关键词**：`<园名> 大门 / 全景 / 鸟瞰 / 航拍 / 迎宾门 / 牌坊`。

**活动类画面（打铁花/演出）不用扔**——放进正文对应的行程节点里（"20:00 打铁花"），**只是不当门面图**。

### 铁律 3｜景点图下方必须有「为什么值得来」简介卡

用户要求：「应该有**精炼的文字**介绍这个**景观的特色**和**游玩的意义**」

**结构**（**60–80 字**，竖版图上 2–3 行）：
```
[📌 为什么值得来] <是什么：规模 + 等级 + 谁做的> —— <对孩子的意义，一句话点题>
```

**已交付范例**（可直接复用句式）：

| 场景 | 文案 |
|---|---|
| 清明上河园 | 依北宋名画《清明上河图》**1:1 复建**的 5A 景区（600 余亩），园内工作人员全着宋装，每天上千场演出 —— **走进去就像入了画，孩子能亲眼看见课本里的汴京活了。** |
| 万岁山 | 以大宋武侠文化为主题的 4A 景区，常年上演《三打祝家庄》等实景剧目，**非遗打铁花**是夜场压轴 —— **武侠梦的启蒙地。** |
| 只有河南 | 中国最大的戏剧聚落群（622亩 · 21个剧场），王潮歌导演作品。以「土地、粮食、传承」为主题 —— **让孩子在戏里认识中原，比讲十遍课本都管用。** |
| 无景点的出发日（代替图） | 河南是**华夏文明的摇篮** ——「一部河南史，半部中国史」，八大古都它占了四个。郑州（商都）→ 中牟（戏）→ 开封（宋）→ 洛阳（唐）。**让孩子把课本里的朝代，走成一条线。** |

**写法要点**：
- **必须有一句"对孩子的意义"**（点题句加粗）—— 这是家长判断"值不值得来"的依据
- 硬知识（规模/等级/年代）不超过一个短句，别写成百科
- 有"世界遗产/最大/唯一/1:1复建"这类**可记住的标签**优先写

### 铁律 4｜文字绝不能遮挡图片上的关键内容

踩过的坑：图片底部叠了半透明文案条「今天去这里｜XXX」，**正好盖住牌坊上的园名字样** → 用户：「配图中字挡住了一些」。

**处理**：
- **删掉图片上的文案条**（图本身有园名 + 下方有简介卡，文案条是冗余）
- 图片用 `object-position: center 32%`（**裁切偏上**），确保大门/匾额/横幅不被裁掉
- **自检方法**：交付前用 vision 看一眼，「图片上的字是否完整可见、有没有被任何元素覆盖」

### 铁律 5｜同一信息不在一个页面/文档里出现两次

**信息分工原则**：

| 信息类型 | 放哪 |
|---|---|
| **价格 / 费用** | **只放底部费用卡**（一处） |
| **怎么用 / 要注意什么** | 行程节点（如"实名分时预约 · 三日有效 · 千场演出全含"）⚠️ **但绝不许写"已预约 / 已购"** —— 票务状态只能来自用户确认，见**铁律 14** |

**保留的"合理重复"**（不算错误，不要过度合并）：
- 去程和返程的同一距离（不同场景）

```
  render_one_page.py（只出单页图，走「⏸ 阶段规则」时用）
```

**批改脚本三条纪律**（某日 实测，一次改 6 份载体没返工）：
1. **一份脚本改全部载体**（JSON 字段级 + HTML 行级），每条 `old` 命中才改，**没命中就报错汇总** ——
   绝不让"静默漏改"混过去（用户看到的会是一半新一半旧）。
2. **`old` 要按文件分别登记**：同一段文案在不同载体里**文字略有差异**（如 `<b>` 位置不同），
   所以「未命中」里通常混着**双胞胎变体**——每份文件只会命中其中一个，**这不是漏改**。
   收尾时按"每份文件至少命中一条主改"核对，别看到 6 条未命中就以为炸了。
3. **改完回读核对**：期望的新表述必须 grep 到、旧表述必须 grep 不到；**数字（电话/金额/时刻）再单独 grep 一遍**
   —— 图上的小字肉眼会看错，这条能挡住最丢脸的一类错误。
**交付前自检**：① 三条源都 grep 到新表述、grep 不到旧表述；② 渲染后 `document.body.scrollHeight`
必须 == **1920**（手账）/ **3508**（A4），超了就是被截断；③ 逐文件核字节+时间戳；
④ 电话号/金额这类数字，渲染完再回到源里 grep 一遍（图上的小字肉眼会看错）。
踩坑：本机 Edge 常没开 CDP 9223 → 用 `playwright.chromium.launch(channel="msedge", headless=True)`
独立起实例渲染，**不要去折腾用户正在用的 Edge 会话**。

### 铁律 10｜给孩子配「A4 横行作文纸」，让他**自己**记录见闻与心情

用户原话：「要生成几张图片再后面，就是**横行作文纸的格式**，孩子们记录**每日见闻和心情**用」

**每天一张**（6 天行程 = 6 张），A4 纵向、可打印 —— 这是**唯一"孩子动手写"的交付物**，
前面所有交付物都是"看"的，这一份是"写"的。

**版面结构**（自上而下）：

```
[Day N 徽章]  <日期>  <当天路线 / 景点>
天气：______   我住在：__________
今天的心情： 😄超开心   🙂挺好   😐一般   😫好累      ← 勾选（不需要孩子写字）
✍️ <当天定制提示语>
──────────────────────────────────  ← 16 行横线（每行 132px，每 4 行一条粗分隔线）
🌟 今天最想记住的一件事：________
[  ✏️ 在这里画下来（想画什么都可以）  ]              ← 虚线框画画区
```

**每天的提示语必须定制**（按当天行程写，告诉孩子"写什么"）—— **这是这张纸的全部价值**：

| 当天类型 | 提示语写法 |
|---|---|
| 赶路日 | 「坐了 3 小时 48 分钟高铁，第一次到中原。写写路上**看到的风景、听到的方言**」 |
| 看戏 / 演出 | 「看了 21 个剧场的戏。**哪一场最打动你**？你看懂了什么？」 |
| **有课本连线的那天** | 「课本里那幅《清明上河图》**活了**。你找到「虹桥」了吗？和书上像不像？」 |
| 有震撼物件 | 「卢舍那大佛 17 米高，比五层楼还高。**站在他脚下抬头看，你在想什么？**」 |
| 返程日 | 「六天走完四座城。**这趟你最喜欢哪里？为什么？**」 |

提示语一律用**第二人称**（铁律 8），并**尽量和当天手账页的「课本连线」呼应**——
孩子白天在手账上看到"你会喊我去过"，晚上这张纸上就会写出来。

**⚠️ 提示语不许绑在「可能停演 / 可能取消」的单一节目上**（某日 用户令：「D3改中性版」）——
**不确定性不只影响行程页，也会打空孩子手上的这张纸**：D3 原写「✍️ **打铁花**那一下，你张嘴了吗？写下你当时的样子。」，
而 10/3 预报有雨、打铁花遇雨大概率临时停演（铁律 25/26）→ 那天孩子只能写"没看到"。
→ 改成**中性版**：「✍️ 今天在武侠城里，你最喜欢哪个角色、哪场大戏？」（**不点任何具体节目名**，看到什么都写得出）。
**判据**：提示语里出现**节目名 / 场次 / 天气依赖项**（打铁花、灯光秀、无人机、游船、夜游）时，
先问一句"**这个万一没上演，孩子还写得出吗？**"；写不出就换中性问法（最喜欢哪个角色 / 哪场戏 / 哪一幕）。
⚠️ 改日记源（`a4/_diary_N.html`）后**必须走下面铁律 23 ⑤ 的日记纸专用收口**（`finish_a4.py` 不含日记纸渲染）。

**⚠️ 两个必踩的坑（某日 实测，连错两版）**：

1. **A4 尺寸必须用 px，不能用 mm** ——
   HTML 里写 `width:210mm; height:297mm` 时，Playwright 在 2480×3508 的 viewport 下
   **不会把 mm 铺满画布**，内容**缩在左上角约 1/4**，右下大半张纸是空白。
   → 正解：**全用 px**，A4@300dpi = **2480 × 3508 px**
   （换算：边距 14/15/10mm → 165/177/118px；行高 10.2mm → 132px；正文 12pt → 50px；Day 徽章 20pt → 83px）。
2. **落版后必须实测总高**：`document.body.scrollHeight` **必须 == 3508**。
   多了会被 `overflow:hidden` **静默裁掉**（本次 17 行时实测 3623 → 超 115px），
   少了就是**下方大片留白**。调整手段只有一个：**增减行数**（**1 行 = 132px**）。
   本次减到 **16 行 = 正好 3508**。

**现成文件（直接复用，别从零写）**：
- 模板 → **`templates/diary_a4.html`**（占位符 `__DAY__` / `__DATE__` / `__ROUTE__` / `__PROMPT__`）
- 生成脚本 → **`scripts/gen_diary.py`**（改顶部 `DAYS` 列表即可换行程，自动渲染 N 张 A4 PNG 并打印每张体积）

一行 11mm 宽，小学生写字刚好」。

**可选的追加问法**（本次主动提给用户，他没有直接要）：

### 铁律 11｜用户说「装订成册」→ 开本要**统一**，A3 大幅面必须重排不能缩放

用户原话：「**都是A3格式吧**，好和**行程手账装订成一本册子**」。

**开本换算表（打印交付物必备）**：

| 开本 | @300dpi 像素 | 比例 | 用在 |
|---|---|---|---|
| A4 竖 | **2480 × 3508** | 1:1.414 | 日记作文纸（铁律 10） |
| **A3 竖** | **3508 × 4961** | 1:1.414 | **装订成册的画册页**（手账 / 路线图 / 日记） |

**统一后要一并考虑的**：

  让用户确认而不是让他自己想。
- 开本一变，**所有页都要跟着改**（手账 6 页 + 日记 6 页 + 路线图），别只改一页。
- 改开本属于"改图"→ **触发铁律 6**（所有嵌图的载体都要重生）。

**A3 版比手机版多两个硬约束**：

1. **原图分辨率必须够** —— 手机版用 1080px 宽的图没问题，**A3 上会糊成色块**。
   内容区宽约 3168px → **原图宽必须 ≥3000px**。
   → 手头图不够大时，**回头找同一景点的高清原图**（本次：D2 换成 4032×3024、"我是河南人"夯土墙；
   D4 有 4608×3456、D5 有 3648×1472 可用）。
   **自检**：`page.evaluate` 打印 `i.naturalWidth`，**远小于内容区宽就是会糊**。
2. **总高必须实测配平到 4961**（同铁律 10 的方法）：`document.body.scrollHeight` 必须 == 4961。
   本次实测路径：5801 →（字号/间距各压一轮）→ 5418 →（再压一轮）→ **4961 正好**。
   **压不动时的调节顺序**：先缩景点图高度 → 再缩字号 → 最后缩节点间距（**别删内容**）。

### 铁律 16｜出门时间按「用户实际住址到站的车程」重算，别套模板——某日 用户令

### 铁律 21｜配图**全篇风格必须统一**；用 AI 生成图必须**在图上可见标注**——某日 D6 实证

**起因**：做 D6（返程日）时发现 `imgs_d6/zoo_hero.jpg` 是**上一轮用文生图模型（Kolors）生成的 AI 插画**
—— 生成脚本 `gen_d6_hero.py` 自己在文件头就写着：

> 「产出是 AI 插画，非实景照片，**交付时必须如实说明**」

而 **D1–D5 用的全是实景照片**。于是同一本手账里出现「5 页实景 + 1 页插画」。

**两条纪律**：

**① 一本手账 / 一套交付物里，配图风格必须统一。**
新加一页前**先看同批页面用的是什么**：
- 同批是**实景照片** → 就从真实照片通道找（Wikimedia Commons / 新闻站 / 百科 CDN，
  见 `creative/image-asset-generation` 的第二条通道），**不要因为手头正好有张 AI 图就用它**。
- 翻到一页风格突变，读的人会"出戏" —— 这跟铁律 2「地标感 > 视觉冲击」是同一层要求：
  **图是给孩子的视觉预期，不是装饰**。

**② 万一必须用 AI 生成图（某天确实搜不到合适实景照片）→ 必须在图上可见地标注。**
```html
<div class="hero-img">
  <img src="...">
  <div class="imgcap">示意图（AI 插画 · 非实景照片）</div>
</div>
```
```css
.imgcap { position:absolute; right:0; bottom:0; background:rgba(0,0,0,.42); color:#fff;
          font-size:15px; padding:2px 10px; border-top-left-radius:10px;
          font-family:"黑体","Microsoft YaHei",sans-serif; }
```
- ⚠️ **图上标了还不够 —— 回复正文里也要说一遍**，并**主动给替代方案**
  （"要统一风格我可以换成实景照片"）。用户对真实性极敏感（「法不轻信」），
  **AI 图不标注 = 失真交付**。
- **生成脚本要在文件头写明**「产出是 AI 插画，非实景照片，交付时必须如实说明」——
  这是给未来会话留的线索（本次正是靠这行字一眼确认出处）。**别省略这句话。**

### 铁律 29｜「做成线上版本」：先定交付形态再谈托管，**国内可达性必须实测** —— 某日 用户令

用户原话：「能做成线上版本，便于手机上查看吗，尤其是能根据实际情况进行更改调整，并给予实时帮助，**去线上仓库看看有没有合适的技能学习**」。

**① 线上仓库调研结论（别重复扒）**：Hermes 聚合库（98k 条）里**旅行类技能全是「生成行程」型**，
**没有**「行程**线上化**」型 —— 这个需求自己做，别指望装个技能解决。真对口的只有两个
`official` 源技能：`web-development/publish-site`（版本化发布 + 本地预览→git tag→HTTP 验证→一键回滚）、
`web-development/cloudflare-temporary-deploy`（零账号即时出公网 URL）。

**② ★ 核心铁律：「部署成功」≠「用户能访问」—— 推荐任何托管前先实测域名可达性。**
本轮实测：`npx wrangler deploy --temporary` **技术上完全跑通**（零账号建临时账号 → 部署成功 → 拿到 URL），
**但 `*.workers.dev` 在国内被 DNS 污染**（`nslookup` 返回 Facebook 的假 IP `2a03:2880:...:face:b00c`、
`curl` 连接 **20 秒超时** HTTP 000）→ **用户手机上根本打不开**。
→ 给国内用户**不要**把 Vercel / Netlify / Cloudflare Pages / GitHub Pages 当默认推荐。
→ 验收动作：`curl -s -m 20 -o /dev/null -w "%{http_code}" <url>`；**测不通就换通道，别说"部署好了"**。

**③ 三条路让他挑**（他常只回一个字母）：**A** 单文件 HTML + 微信传（离线也能看 ·「添加到主屏幕」像 App · 0 成本、不用账号）｜
**B** 国内静态托管（腾讯云 COS / 阿里云 OSS / Gitee Pages —— 真公网 URL，需账号）｜
**C** 在线文档（腾讯文档 / 飞书 —— 他自己手机上就能改，排版弱）。

**④「实时帮助」不许空口承诺**：用户旅行中**只有手机、家里电脑不在** → 真·AI 对话需要额外一台公网后端，
当前**没有通道**。→ 如实说明边界，落到**离线应急卡**：按「每种意外给 2–3 条备选」写
（叫不到车三层兜底 / 雨天停演改室内 / 走错站纠错 / 联系电话），而不是泛泛的「注意事项」。
❌ 不要承诺「页面里能问 AI」，也不要建议他「早上开机跑一下」这类他拿不到的方案。

**⑤ 流程沿用铁律 28**：先出 **D1 样张** → 确认样式 → 再铺 D2–D6 + 附录。
样张可直接 `desktop_preview` 打开本地 HTML 让他看；**内容层在选哪种托管时都能复用，所以样张不白做**。

**⑥ 内容源提示**：A4 装订册 PDF 是**图片拼的、无文字层**（`read_file` 报 Binary file）→
取内容要回 `.docx` 攻略（有完整文字层，本项目 269 行）或直接读手账图。

## 本机实现要点（HTML 手账图路线）

9:16 手账图在本机**不用文生图模型**（实测中文必乱码、结构必丢），走 **HTML/CSS 渲染 → 截图**。
完整骨架、色系、渲染脚本见 `life/travel-scrapbook-itinerary` 的「本机适配」节。补充要点：

- 画布 `1080×1920` 精确 9:16；顶部景点大图高度 **238–240px** 为实测最佳
- **⚠️ 换了配图，必须同步「为什么值得来」卡**（某日 实证）：把 D5 配图从「莲鹤方壶」换成
  「博物院外景」后，下方简介卡还写着贾湖骨笛/妇好鸮尊/莲鹤方壶 —— ① **图文不符**，
  ② 那段内容和节点 5 的「九大镇院之宝动线」**重复**（违反铁律 5）。
  → **换图三件事**：a) 简介卡改成讲**新图里那个东西**（本次改成讲建筑：「主展馆是**戴冠的金字塔**造型 ——
  以登封元代观星台为原型，外墙取中原黄土之色」）；b) 顺手删掉与新图无关的重复信息（省高度）；
  c) 交付前 vision 看一遍"图和在讲的字是不是同一件事"。
- **⚠️ `object-position` 必须按每张原图的构图试，不能照抄上一张的值**（某日 连调 3 次才准）：
  这条横带只有 **180px 高 × 1028px 宽（≈5.7:1）**，`object-fit:cover` 只保留原图的**一条横幅**。
  - **主体居中的方图 / 竖图**（文物特写、建筑正立面）→ `object-position:center 16%` 就够（莲鹤方壶实测值）
  - **远景 / 天空占大半的横图** → 要**调大**才取到下方主体。本次博物院远景：`30%` 只剩塔尖＋一片蓝天、
    `68%` 取到建筑中下部（**塔尖被切**）、**`47%` 才正确**（造型完整 + 上方留一丝天空）
  - **诊断口诀**：**画面里出现大面积天空/空白 = 窗口取高了 → 把百分比调大**；
    **主体被切（塔尖/底座没了）= 取低了 → 调小**。
  - 一次渲染只要几秒 → **用 2–3 次逼近即可，别想着一次算准**；每次渲染后 vision 复核。
- **删 HTML 块用 div 配对计数**，别用非贪婪正则（会只删外框、留下内层块 → 图删不干净）
  → 现成工具：**`scripts/strip_block.py`** —— `strip_class_blocks()` 按 div 配对删整块、
  `strip_any_class_blocks()` 兜底（class 属性不在首位时）、`count_images()` 用 `<img` 数量判断
  "删干净了吗"，文件末尾带自检可直接 `python strip_block.py` 跑
- 删图后加 `body { display:flex; flex-direction:column; justify-content:space-between; }` 吃掉留白
  — ⚠️ **但加了 flex 就必须同时给关键区块加 `flex-shrink:0`**（某日 在 A3 版上踩到，排查了两轮）：
  flex 布局在**内容总高超出画布**时会**主动压缩子元素**。症状极其迷惑 ——
  **顶部景点图被挤成一条约 60px 的细条**（明明 CSS 里写的是 `height:560px`），
  同时 `document.images` 里 **`naturalWidth` 显示正常（4032）**，所以第一轮误判成"图片没加载"。
  → 修法：给 `.head` / `.hero-img` / `.intro` / `.booklink` / `.route` / `.bottom` / `.bubbles`
  这些**固定内容块逐个加 `flex-shrink:0`**。
  **判别口诀**：**flex 填留白是"内容不够"时用；一旦内容超出，flex 就会反噬去压元素** ——
  这时正确的下一步是**缩内容**（铁律 11 的调节顺序），而不是继续调图片路径。
  自检：`page.evaluate` 量出关键块的实际 `getBoundingClientRect().height`，与 CSS 声明值对不上就是被压了。
  **⚠️ `scrollHeight == 1920` 完全不能证明没被压**（某日 实测）：
  被 flex 压缩时 `body` 依然是 `height:1920`，`scrollHeight` 照样等于 1920 —— **看不出任何异常**，
  而景点图可能已经被挤成 48px 的细条。**必须把 body 临时改成 `height:auto` 再量真实内容高**：
  ```js
  const b = document.body, old = b.style.height;
  b.style.height = 'auto'; const real = b.scrollHeight; b.style.height = old;
  // real - 1920 > 0 → 超标多少；同时量 .hero-img 实际高对不对得上 CSS 声明值
  ```
  **分页差异化压缩（各页内容量差很多时，千万别一刀切）**：
  本次实测真实高 D1 1711 / D2 2061 / D3 2118 / D4 2037 / D5 1813 —— 统一压字号会把 D1/D5 压到
  1466 / 1593（余 450+），`space-between` 把空白摊到每个块之间，看着就是「这页没排满」。
  → **正确顺序**：① 只对**超标**的页压字号/间距（间距→字号，按铁律 11 顺序）；
  ② 压完把**景点图恢复到原始高度 238–240px**（它才是被压的受害者）；③ 再对**余量过大**的页做"轻度回补"
  （字号 +2、节点间距 +3、内边距 +2），把每页余量收进 **80–210px**；④ 最后才加 `flex-shrink:0` 兜底。
  本次三个可复用脚本：`apply_food_boat.py`（批改载体）、`apply_compact.py`（压）、`fix_layout.py`（回补配平），
  均在 `$HOME\.hermes\tmp\henan\`。
- **⚠️ 编号圆点"从第 3 个起整列消失" = `.route` 被多余的 `</div>` 提前闭合**（某日 实测 D1/D2 各 5 处 / 4 处）：
  症状极具迷惑性 —— 卡片、文字、`scrollHeight` **全都正常**，只有左侧 3 号之后的编号圆点不见了。
  根因：HTML 里多写了一个 `      </div>` → `.route` 提前闭合 → 后面的 `.node` 掉到 `<body>` 下，
  `.dot` 的 `left:-52px` 变成相对 **body** 定位 → **x = -26px，被 `overflow:hidden` 裁到画布外**。
  → **诊断（一眼定性，别靠肉眼看图猜）**：
  ```js
  document.querySelector('.route').children.length   // 应 == 节点数；只有 2 就是结构坏了
  [...document.querySelectorAll('.node')].map(n => n.parentElement.tagName)  // 出现 "BODY" = 漏出去了
  [...document.querySelectorAll('.dot')].map(d => Math.round(d.getBoundingClientRect().x))  // 负数 = 被裁
  ```
  → 修法：删掉多余的 `</div>` ——正则 `\n      </div>\n      </div>\n    </div>` → `\n      </div>\n    </div>`，
  **带空行的变体**（`\n      </div>\n      \n      </div>\n    </div>`）再跑一遍。改完重新量真实高：
  `.node` 回到 `.route` 内会**变窄 68px**，长文本可能多换行 → 高度会变。
- 搜图过滤付费图库/水印站：
  `nipic|vjshi|699pic|dashangu|3158|zcool|58pic|zhitu|huitu|qiantu|ibaotu|tuchong|veer|sheitu|pconline|588ku|redocn`
  → 优先**新闻站 / 百科**（新浪、大河网、百度百科、知乎、携程 CDN）
- 截图用 Playwright 连本机 Edge CDP（`http://127.0.0.1:9223`），**别用 `chromium.launch()`**（本机没下浏览器）
- **每页用不同主色区分**（如赶路日=蓝、戏剧=朱红、武侠=棕、宋园=青绿），翻阅时一眼定位
- **PowerShell 变量拼接必须加花括号**：`"$dst\$d手账图.png"` 里 `$d手账图` 会被当成**一个变量名**
  （中文/`-`/数字都是合法变量字符）→ 未定义取空 → 路径塌缩成同一个文件 →
  **循环 5 次全部写到同一个文件**（症状：交付目录里每个文件大小完全一样）。

  或直接分两句输出。同类 PS7-only 语法（`?:`、`??`、`&&`）在本机也不要依赖自动降级。
- **⚠️ 别用 `python -c @" ... "@` 内联含 emoji / 中文的代码**（某日 连崩两次）：
  PowerShell 会对内联字符串做转义/编码处理，含 emoji（如 `📍`）的 Python 字符串会报
  `SyntaxError: unterminated string literal`，而且**脚本根本没执行**，只留下一个报错。
  → **一律改用 `write_file` 把脚本落盘成 `.py` 再 `python xxx.py`**，稳得多。

  症状：`UserWarning: Glyph 128661 (\N{TAXI}) missing from font(s) KaiTi`。
  **PIL + `msyh.ttc` 同样缺 emoji 字形**（某日 实测：竖版路线图 D1–D6 后接「🏨 住…」→ 交付前 vision 读出来是「□ 丽呈…」，就是豆腐块）。
  修法：图里的文字**不要用 emoji**，改用中文词（`住：` / `打车` / `高铁` 而非 🏨 / 🚕 / 🚄）。
  ⚠️ **判据：只要交付图是 PIL/matplotlib 直画的（不是浏览器渲的），落盘前必颏 vision 看一遍有没有方块** ——
  脚本只会报"没超框"，豆腐块它一句也不会吐。
  批量清理：正则 `[\U0001F300-\U0001FAFF\u2600-\u27BF]` 扫一遍替换掉
  （注意：**逐条 `str.replace` 容易漏**，实测漏掉 2 个残留，正则一次清干净）。
  HTML 渲染路线不受影响（浏览器有 emoji 字体），**只有 matplotlib 出图要注意**。
- **⚠️ Playwright 截含大图的页面会超时**：`Page.screenshot: Timeout 30000ms exceeded`
  （日志停在 `waiting for fonts to load... fonts loaded` 之后）。
  触发场景：刚重启的 Edge + `file://` 加载 100KB+ 的 PNG。
  修法：**截图前等图片真正加载完成 + 加大超时**：
  ```python
  page.goto(url, wait_until="load", timeout=90000)
  page.wait_for_function("Array.from(document.images).every(i => i.complete)", timeout=60000)
  page.wait_for_timeout(2500)
  page.screenshot(path=out, clip={...}, timeout=90000)
  ```
  并顺手打印真实图尺寸做校验：`page.evaluate("Array.from(document.images).map(i=>i.naturalWidth+'x'+i.naturalHeight)")`
  —— 输出 `0x0` 说明图没加载上，别急着交付。
- **路线图/示意图的"线↔文字"压线问题，脚本自检查不到**：`matplotlib` 版自检只比对
  **文字↔文字** 的 bbox，弧线穿过标题这类问题它会报"✅ 无重叠"。
  常见成因与修法：① `FancyArrowPatch(rad=…)` 过大 → `rad` 压到 **0.10–0.15**；
  ② 标注框正好落在线条路径上 → 移到**线条外侧**；③ 相邻标注框太近 → 拉开 ≥0.4 坐标单位；
  ④ 无底色小字被箭头压住 → 加圆角底色框、字号 ≥10.5。
  **交付前一律用 vision 逐张看图**，不能只信脚本。
- **⚠️ 示意图里「点」和「线」必须用同一坐标系**（某日 连错两版才修对；用户报的
  "文字和连线位置不对"根因就在这）：
  典型错法 —— 城市圆点用 **CSS 百分比定位**（如 `left:16%; top:38%` + `transform:translate(-50%,-50%)`），
  连线却用 **SVG `viewBox` 绝对坐标**。两套坐标系互不换算 → **圆点集体跑偏、连线全部悬空对不上**。
  **正解：整张示意图全用 SVG** —— `<circle>`（城市）+ `<text>`（标签，显式写 `font-family`）+
  `<path>`（路线 + `<polygon>` 箭头）共享同一个 `viewBox`，点、线、标签天生严格对齐。
  （纯 CSS 方案也能做对，但必须让圆点和连线共用同一套 px/百分比并逐端点核对，成本高得多。）
- **⚠️ 示意图坐标必须用真实地理，不许手工摆位**（某日 连错三版；用户原话
  「感觉你画的小地图**城市位置不对，包括距离**，最后能**按照中国地图的形式**？」）：
  - **旧做法已废弃**：曾用"人工拉开纵向间距换可读性 + 图注写'南北向已压缩'"糊过去
    —— 用户**不接受**，他看得出位置和距离是编的。
  - **正解：真实 GeoJSON 省界 + 经纬度投影 + 大圆距离**，一步到位。
  - **难点与解法**：本项目 5 城纬度跨度 28°N–35°N，而河南四城只差 **0.2° 纬度**
    （洛阳/郑州/中牟/开封经度差 1.86°）→ 等比例画会**挤成一团**。
    → 用 **「主图（湖南+河南全省界）+ 插图（河南四城放大框）」** 双视图解决，
    主图上用红色虚线框标出放大区域，插图标题写「河南四城（放大）」。**不靠改比例骗人**。

    文档里写哪个口径就在图上标哪个，或两者都标 —— **不要让同一段路在两张图里数字打架**。
- **路线图有两个方向，按场景选**：

  | **横版** | matplotlib 手绘风宽幅 PNG | Word「出行概览」之后 |

  （每天一张卡：路线 + 交通 + 景点 + `住哪` 胶囊）→ 底部要点胶囊（如"高铁3段 / 只搬2次酒店 / 仅D5需08:20出发"）。
  字体、米色网格纸、白卡、阴影、胶带**全部沿用 9:16 手账图**。
- **⚠️ PIL 手工合成页（竖版路线图 / A4 路线图页 `p02.jpg`）必须先量字宽再落盘**

### 铁律 22｜**零余量页加内容：只能挪「间距」，不许压「字号」**（某日 D5 课本连线实证）

**触发**：往某页手账图加/换一块内容时。**先量，再改。**

**第一步：量三个数**（`~/.hermes/tmp/henan/measure_pages.py` 一把出全页）：
```powershell
python measure_pages.py     # 输出每页 真实高 / 余量 / head·hero-img·intro·booklink·route·bottom·foodbar·bubbles
```
判据：
- **余量 ≥ 要加的高度** → 直接加。
- **余量 < 0（或 = 0）** → 这页是**零余量页**（D5 实测 1920 恰好）。★此时**砍文字往往没用** ——
  文字只要不跨行数减少，`.booklink` 高度**一动不动**（D5 实测：精简 20 余字，`booklink` 仍 147px）。
  **改法只有两条：从别处挪间距，或把内容下沉到 Word（铁律 19）。**
- **顺手看 `hero-img`**：D5 = **187px**（D4 212 / D3 245 / D2 247）→ **低于 238 说明它已被 flex 压过**，
  这页本就到临界，不是"还有空间"。

**第二步：只调这些「间距旋钮」，按省量从大到小逐档试、够了立刻停**

| 旋钮 | D5 实测 | 省 |
|:--|:--|--:|
| `.node { margin-bottom:5px → 2px }`（×6 节点） | 命中 1 处 | **−18px** |
| `.card { padding:7px 15px → 5px 15px }`（×6 卡） | 命中 1 处 | **−20px** |
| `margin:0 0 8px 0 → 5px`（intro / booklink 两块，用 replace 全部命中） | 命中 2 处 | **−6px** |
| `.bottom { margin-top:6px → 3px }` | 备用 | −3px |
| `.hero { padding:11px 19px → 9px 19px }` | 备用 | −4px |

⚠️ **绝不碰 `font-size`**：D5 的 `.booklink` 是 21px，与 D4/D3 一致；压成 20px 会**两页不齐**（一眼看得出）。
除非全批页面一起压（那要走铁律 14 的"密度回补"流程）。

**第三步：批改脚本三条护栏**（本轮全踩过，缺一条就会交出错的东西）
1. **断言命中才改**：`if old not in src: raise SystemExit("断言失败…")` —— 本轮正是它挡住了
   "旧串里我写了 `&amp;` 而原文是字面 `&`"的错误替换。
2. **超框就不落盘**：量到 `real > 1920` 就 `raise`，**先渲染不写桌面** ——
   否则 `overflow:hidden` 会**静默截断**，你交出去一张缺尾巴的图还不知道。
3. **备份文件名要 sanitize**：`re.sub(r"[^0-9A-Za-z]+","_",label)` ——
   直接用中文标签（如 `intro/booklink`）拼路径会因含 `/` 报 `FileNotFoundError` 中断整个批改。

**第四步（本次补充）**：改完跑 **vision 复核**，重点看"**新加的那段有没有和页面上别处重复**"——
本轮 D4 我加的「照画 1:1 复建」与上方简介卡的「1:1 复建」撞了（铁律 5），是 vision 看出来的，脚本自检查不到。

### 铁律 23｜多载体**版本漂移**体检 + 零余量页不许回补 + 「全部更新」型指令＝全执行（某日 实证）

**① 同一行程的「变体 HTML」各自独立维护，会漂移成僵尸页 —— 必须逐个体检。**
本机管线里 A4 页不是从手账源渲染的，而是**另一份独立 HTML**（`a4/dX_a4.html`）。
某日 实测：`scrapbook/d5.html` 已是「开封→郑州·河南博物院」，
而 `a4/d5_a4.html` **整页仍是已作废的「洛阳·龙门石窟」**（洛阳×10、龙门×12）——
手账图全对，**A4 册与 PDF 里的 D5 却是错行程**；同类还发现 a4 版写着「门票约 400 元」（订单实付 300）。

**体检手法（一条命令定位全部漂移页）**：对每个变体文件做**关键词计数**，看它属于哪一版：
```python
for kw in ['洛阳','龙门','郑州','中牟','开封','博物院','万岁山','清明上河园','二七']:
    print(kw, body_text.count(kw))
```
**某一版特有的城市名计数 >0、新版的地标计数 =0 ⇒ 这页是旧版。** 改版（换城市/换景点）后必须
**逐个变体页体检**，别假设"上游改了它就跟着改"；变体页里的**数字**（票价、时长）也会单独过期。

**② 「腾出空间」≠「有余量」——删内容后仍不许回补。**
铁律 14 / 22 讲「删完回补密度」，但**回补的前提是量出来有余量**：
D5 删掉两句（课本连线半句 + 薄外套）后 `scrollHeight` **仍是 1920**（flex 撑满画布）、`hero-img` 停在 180px
—— 此时**不能按铁律 14 去补 hero 高度，补一 px 就超框被静默截断**。
→ **判据永远是 `body{height:auto}` 量出的真实内容高**；删文字若不减少行数，高度一动不动（同铁律 22 的发现）。

### 铁律 24｜末班日 / 半日空档选点：按「双向实测车程 + 用户作息」筛，别推荐"来回 3 小时"的景点 —— 某日 D6 实证

**三条判据**：
1. **单程 ≤ 约 20 分钟车程（≈10 km）** 才叫"睡到自然醒也能玩透"；**>30 分钟必须同时给替代方案**。
2. **算"回得来"而不是"顺不顺路"**：末班日行李常寄存酒店 → 动线是 `景点 → 酒店取行李 → 车站`，
   "离车站近"没用，要看**酒店↔景点的往返车程**（本轮 1.6 km/11 分的动物园、9.9 km/24 分的自然博物馆才是正解）。
3. **时间账从用户起床时间倒排，不许默认 7:00 起**：用户原话「**D6 起床没有那么早，起床都要 8 点**」
   → 按 **08:00 起 → 08:45 早餐 → 09:10 退房（行李寄存前台）→ 09:20 打车 → 14:45 回酒店取行李 → 15:45 出发去车站** 排；
   自己写出的 07:00 早起版必须**标注"若要 8 点起就砍哪个节点"**，或直接给两版让他挑。

**候选筛法（一次测完，别一个个试）**：高德批量出「酒店→X」「X→车站」两列
（配方与脚本见 `references/halfday-slot-and-show-uncertainty.md`），再按
**车程 → 孩子适配（动物园/博物馆/恐龙厅 > 看建筑）→ 门票与预约门槛 → 雨天可退性** 排序；
**同一份表里把 `门票 / 开放时间 / 是否要预约` 一起给**，别让他再问一轮。

**附则 A｜筛选阈值跟着「可用窗口」走，别把半日判据套在全天上**（某日 当晚用户改口）：
用户先说「D6 起床都要 8 点」（半日窗），随后明确「**D6 是全天备选，从早上 8 点到下午 4 点都是可以自由活动的**」

**动作**：每次听到作息/窗口变化，**重跑一遍候选表并按新窗口重排**，别沿用上一轮的取舍；
窗口口径要写在交付物最显眼处（图上 D6 那一行 + Word 附录「前提」段）。

### 铁律 26｜「把天气加进去」类指令：**按天原位填占位块 + 必须声明预报性质 + 雨备联动** —— 某日 实证

用户原话：「还有查一下天气情况，**把当天的天气都加进去了**」。

**① 数据怎么拿（中国天气网 15 天预报）**：
- 15 天页 `http://www.weather.com.cn/weather15d/<cityCode>.shtml` 是 **JS 渲染** 的 ——
  `urllib` 抓回来是**空表格**（有日期无温度）→ **必须用 Playwright 浏览器渲染后读 `innerText`**。
- 别拿 `d1.weather.com.cn/calendar_new/...` 冒充预报：它给的是**概率/气候值**（如 `33%`），**没有天气现象**。

⚠️ **换字会改框宽 → 换完必须重量真实高**（`body{height:auto}`；本轮 6/6 页仍 1920 == 目标高）。

**③ 雨备联动（天气信息的真正价值）**：预报不只是温度 —— 把**当天最怕的雨**写成行动提示：

### 铁律 27｜「我要准备打印了」→ 跑**打印前总检**，把「疑问」编成号交给用户 —— 某日 深夜实证

触发句：「**全部再检查一下，有问题疑问的都可以找我确认，我要准备打印了**」。
这是交付的**最后一个动作**，与铁律 23（多载体收口）不是同一件事：23 修的是"改完这处、还有哪些没跟着改"；
27 查的是"**整包东西能不能直接送打印店**"。

**四步总检 → 现成脚本 `scripts/preprint_audit.py`**（改顶部 CONFIG 即可复用，输出六段）：
1. **清单与规格**：逐个核 文件在不在 / 像素（手账与片单 1080×1920 · A4 与日记纸 2480×3508）/
   PDF 页数与每页尺寸（A4 = 595×842pt = 2480×3508@300dpi）。
2. **跨载体事实抽查**：把当轮改过的关键串写成 `{事实: [应含它的源]}` 表，缺一即 ❌。
3. **旧口径扫描**（`scripts/scan_stale.py`）：旧地名/旧里程/旧车次/旧时间/旧方案词 + `待确认|待定|待实时查询`。
   ⚠️ **命中要人工判**：本轮 6 处「洛阳」里 3 处是「**洛阳水席**」、2 处是**已弃用的旧版源**
   （`d2_v2/v3.html`、`map_v.html` 没被任何渲染脚本点名），真正在用且带旧行程的只有 `scrapbook/_diary_5/6.html`。
   → **判据：先确认这个文件是不是当前在用的源**（`finish_a4.py` / `render_*.py` 里点名的才算），
   别把弃用文件当交付缺陷，也别把真正在用的那个放过去。
4. **vision 抽检 2–3 张最脏的页**（数值对 ≠ 没裁字 / 没被 flex 压扁）。

**两个必踩的坑（本轮实例）**：
- **① 「时间链」只改了一半 —— 打印前最容易漏的一类。** 用户改口「D6 起床 8 点 / 全天自由活动 8:00–16:00」后，
  **竖版路线图按新窗口写了 16:00 取行李，而手账图 + A4 + Word 三处全停在旧链**
  （`07:00 起 / 15:30 取行李 / 15:45 打车 / 16:20 到站·留 100 分`）。
  → **反查词（逐载体 grep）**：`起床` · `取行李` · `打车` · `到站` · `留 N 分钟`；
  改作息/窗口/发车时刻时，**这四个数必须成组一起改**，且改完把它写进 memory（本轮已写）。
- **② 「未被使用的旧副本」会混进总检结果**：桌面 `日记作文纸\` 里 6 张还是 9/18 的旧图，
  而 `A4装订册\` 里已是新版 → 打印前**把两个目录同步**（或明确告诉他打哪个目录），
  否则他可能打了旧的那份（同铁律 6 的"同一张图几个载体"）。

**交付格式：体检结果 + 编号疑问清单**（他要的是"能回编号"）：
- 正文三段：**已修 N 项**（每条一句、带「原值 → 新值」）→ **全套状态表**（载体 / 规格 / ✅）
  → **请确认的 3–4 件**（编号）。
- 疑问只放**真正要他拍板的**：① 时间口径（给 A/B 两个时刻、各带缓冲分钟）② 未购票项买不买
  ③ 写死的事件型提示（如"打铁花"）是否改中性 ④ 打印范围（要不要只含手账页的 PDF）。
- 末尾固定两句话：**A4 打印按「实际大小 100% 不缩放」**；**9:16 手账图是手机看的、打印会拉长不建议**；
  天气/演出属趋势信息、**出行前 3 天复核**。
