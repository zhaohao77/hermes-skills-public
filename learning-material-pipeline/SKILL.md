# 📚 学习材料流水线

> 分工：**`teach` 管教学法**（mission / 节彗 / 最近发展区），**本技能管材料与保真**（原文从哪来、引文是不是真的、学完沉到哪里）。
> 两者一起用：先跑本技能拿到干净原文 → 再按 `teach` 出课。

## 何时用

- 用户说“教你读这本书”“把这本学透”“按书出一节课”
- 要把一本书 / 一门课 / 一堆文章变成“可信的”学习材料（不是搜索或摘要）
- 需要验证“课程里那句话是不是原文说的”

## 一、取原文：优先级与验收

**优先级：PDF 文字版 > 网页截图 OCR > 只有划线/摘要。**

1. **先问他有没有电子版、存在哪**（网盘/本地/微信读书书架）。存量文件往往比拓网快十倍。
2. **拿到 PDF 先判是不是文字版**：`pymupdf` → `page.get_text()`；全书 0 字 = 扫描版，先找有没有更小的文字版，别直接上 OCR。
3. **报三个数当验收**：页数 / 字符数 / 汉字数，并与出版社标称字数对得上（例：标 13.1 万字 → 抽 11.3 万汉字 = 对得上）。
4. **微信读书网页版正文是 SVG 图形渲染**（0 个文本节点、数百个 path），DOM 取不到 → 只能“逐屏截图 + 视觉模型逐字转录”。这是**降级通道**，不是首选。

具体链路（网盘搜索与直下、Weread 页面结构与翻页、字节校验）→ `references/book-source-acquisition.md`

## 二、引文核验（硬门槛，出课必跑）

课程里每段 `<blockquote>` 必须是原文的**连续片段**（逐字或节引），**不许拿自己的话冒充引用**。

```bash
python scripts/verify_quotes.py <lesson.html> <原文.txt>
```

口径：逐句算「子序列覆盖率」＝ difflib 匹配块总长 ÷ 句长。

| 覆盖率 | 判定 | 动作 |
|:--|:--|:--|
| 1.000 | 逐字引用 | 过 |
| 0.95–0.99 | 节引（只删未改） | 过（建议在引用里标“……”，标清省了哪句） |
| < 0.95 | 有改写 | **改回原文再交付** |

- 实测教训：一篇课 12 段引文里查出 2 段是压缩改写（算式那段、三条并列措施那段），改回原文后全绿才交付。
- **自己先跑，别等用户来问“这是原文还是你编的”**——这一问一旦问出来，整份材料的可信度就掉一半。
- 用户自己划的线 / 笔记只能当“关注点排序”，**不能当原文来源**。

## 三、出课：交接给教学层

拿到干净原文后，按 `teach` 的规矩出课（一节一个成果、可离线打开、带引用、一节一交付）。
本技能只保证**材料是真的、可回查的**，不管教学法。

## 四、沉淀：卡片分层，宁少勿多

| 时机 | 产出 | 放到哪 |
|:--|:--|:--|
| 单元/一节课学完 | 只记真实使用（说了几次 / 接住几次 / 原话） | 课堂目录的 `drill/回收台账.md` |
| 学完一整本（或攒够 5 条） | 归类去重→ 5–8 张「场面卡」→ **并进用户已有的操作台** | 例：`management-os` 的「场面直通车」 |
| 只有当一套动作跨书跨场景复用、有唯一触发句、自带自检 | 才考虑做技能 | 走 `materials-to-skill` 的伪技能自查 |

**铁律：一本书 ≠ 一个技能。** 用户技能库已 400+，再加一本就多一个抢路由的入口；卡片进“他真会打开的那个文件”才有价值。

## 五、本机适配（Windows / Hermes Desktop）

| # | 事项 | 做法 |
|:-:|:--|:--|
| 1 | 长脚本/目录名 | 课程目录、脚本文件名用**英文/数字**避 GBK 坑；课堂目录可中文（`人生规划\teach-<主题>\`） |
| 2 | 打开成品 | `msedge --new-window "file:///C:/..."`，然后 **`Get-Process msedge` 查 `MainWindowTitle`** 确认真开了（“文件写好了”≠“他看到了”） |
| 3 | 路径 | 一律 `C:/Users/...` 正斜杠；原生程序（python/node）不认 MSYS 路径 |
| 4 | 中文内容写文件 | 用 `write_file`，不要塞进 `python -c` 或 heredoc（引号/转义会碎） |

## 六、坑（都是实踩）

1. **“找到 0 个”几乎总是脚本 bug，不是库里真没有。** 扫描脚本必输出两个数：访问了 N 个目录 / 命中 M 项；N 正常 M=0 → 匹配逻辑或路径拼错。
2. **按路径下载失败（errno=2）时改走 fs_id**：搜索/列目录拿 `fs_id` → filemetas 取 dlink → 拼 `access_token` → 直下 → **比字节数**。
3. **同一账号多条通道会互相覆盖**：微信读书的阅读进度会被另一端翻页同步掉 → “定位+截图+转录”必须**单进程一次跑完**，不要分两次脚本。
4. **网页目录面板是虚拟列表**（元素 `getBoundingClientRect()` 全 0）→ 点不动；靠“回翻 + 章节名监测”定位更稳。
5. **OCR 稿要做交叉核**：与 PDF 文字版比相似度，差值集中在导航文字上属正常；若正文段落相似度 < 0.9，别直接用来出课。

## 七、交付话术（用户认这个顺序）

1. 材料怎么来的（网盘/PDF/OCR，字节或字数校验）
2. 拿到多少（页数 / 字符 / 汉字，与标称对得上）
3. 引文核验结果（几段、最低覆盖率、有没有改回原文）
4. 下一步学哪节、要他说什么
